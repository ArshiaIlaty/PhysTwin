Force-Aware Learning in PhysTwin:
Open-Loop Characterization & Closed-Loop Control

Two complementary research tracks built on the PhysTwin spring-mass simulator — predicting contact force from deformation, and commanding force through learned gripper policies.

Overview

This is not a vision-language-action (VLA) policy. We operate inside a physics-informed digital twin fitted from real videos. Inputs are compact deformation descriptors over simulated particles; outputs are 3D contact wrenches or gripper motions. Labels come from the simulator’s spring forces — not from physical force sensors.

Why this setting is novel

Prior work such as PhysTwin focuses on reconstructing geometry and physics from video, then simulating under human or keyboard control. We extend the simulator into a force-aware learning testbed: (1) counterfactual physics sweeps without new videos, and (2) learned mappings between deformation and wrench — forward and inverse — with explicit train/test splits that separate within-trajectory interpolation from cross-manipulation generalization.

Problem Setup

Ground truth forces are computed inside PhysTwin’s optimized spring-mass model: for each control group, spring forces between gripper points and object particles are summed into a per-group wrench, then aggregated into a net wrench y_net ∈ ℝ³.

What the 35-dim descriptor captures

Variable particle counts are collapsed into fixed-size statistics — no raw point cloud at inference:

  • Shape change — centroid displacement, bounding-box deformation
  • Motion — velocity magnitudes, kinetic-energy-like terms
  • Contact — distance from particles to controller
  • Context — material category one-hot

Arshia Open-Loop Physics Sweeps

Teacher forcing: replay a fixed synthetic gripper script with no feedback. The only variables are physics knobs — object stiffness (×0.5, ×1.0, ×2.0) and surface proxies (concrete, grass, rubber). Same motion every time; measure how peak contact force responds.

  1. Pick donor case per material (cloth, rope, sloth) and a motion script (hold_release or linear_push).
  2. Replay identical controller trajectory while scaling stiffness and swapping surface friction/restitution.
  3. Record per-frame net wrench from the simulator — 27 scenarios (54 in expanded grid).
  4. Plot peak force vs stiffness and force trajectories over time.

Arshia Forward ML — Deformation → Force

A per-material MLP maps summary features to net wrench. Training uses 12 real PhysTwin cases in dataset_v2. We report two evaluation modes that answer different generalization questions.

Split Question How it works Cloth R² Rope R²
cross_case New manipulation held out? Entire test case unseen (e.g. train 3 cloth cases → test single_clift_cloth_1) 0.62 negative*
random_block Unseen frames in same trajectory? Hold out ~20% contiguous frame blocks per case (not random single frames, not physics perturbations) 0.90 ± 0.05 0.59 ± 0.05

*Rope cross-case: train single-hand push → test two-hand (rope_double_hand) — regime mismatch + small N, not under-training.

Running example — cloth hold-release

  1. Simulator runs case single_clift_cloth_3 with recorded gripper motion.
  2. Each frame: particle positions → 35 summary features → label = sim net wrench.
  3. Train per-category MLP on other cloth cases; test on held-out frame blocks.
  4. Compare predicted |F| vs simulator |F| over time.

Malak Closed-Loop Force Control

Student forcing: a learned policy replaces the human keyboard. Each timestep it observes deformation state and a force goal, outputs gripper displacement, and the simulator advances one frame. The real evaluation is whether achieved force tracks target force in live rollouts — not just held-out frame R².

Running example — replay test on cloth

  1. Reset PhysTwin to frame 0 of a test case (e.g. double_lift_cloth_1).
  2. Set target trajectory F_goal[t] to the recorded force of that case (replay mode).
  3. At each step: observe X_t, current force → policy → gripper Δ → sim step.
  4. Plot achieved |F|(t) vs target |F|(t). Diagonal scatter = perfect tracking.

Future Work

  • Latent stiffness embedding — categorize / condition on material stiffness without explicit knobs
  • Temporal backbone — transformer or GRU over feature windows instead of frame-independent MLP
  • Context adapter — inject external task descriptions (VLA-style summarization) into the policy
  • More qualitative demos — side-by-side stiffness videos, closed-loop rollout recordings
